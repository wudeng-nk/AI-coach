# AI Coach 系统 - 产品需求文档 (PRD)

## 一、项目概述

### 1.1 产品定位
AI Coach 是一套面向销售人员的智能培训与辅助系统，通过 AI 驱动的知识库问答和模拟客户对话训练，帮助销售人员提升产品认知和销售技能。

### 1.2 目标用户
- 销售/课程顾问（主要用户）
- 销售主管/培训负责人（管理角色）

### 1.3 核心价值
- 随时获取产品知识与销售技巧
- 低成本、高频率的销售场景模拟训练
- AI 自动化点评，提供个性化改进建议

## 二、系统架构概览

### 2.1 架构原则
- **本系统只负责前端界面 + 后端业务逻辑（会话管理、数据持久化、流程编排）**
- **所有 AI 智能体能力（知识库问答、模拟客户对话、教练评分）均通过 HTTPS 接口对接外部 AI 服务**
- 后端作为统一网关，代理前端与外部 AI 服务之间的通信

### 2.4 外部 AI 服务接口契约

```

{
  "answer": "string",                // 回答内容
  "sources": ["string"],             // 来源引用
  "category": "string",              // 问题分类（产品知识/销售技巧/其他）
  "suggestions": ["string"]          // 推荐的后续问题
}
```

#### 模拟客户对话服务

```
POST {AI_SERVICE_BASE}/customer/chat

{
  "customer_id": "string",           // 模拟客户ID

  "message": "string",               // 用户发送的消息
```

## 三、功能模块详细需求

### 模块一：知识库问答

#### 3.1 功能描述
用户通过自然语言聊天的方式提问，后端将请求转发至**外部知识库问答服务**（HTTPS 接口），获取回答后返回给前端展示。本系统负责对话上下文管理、历史记录存储和界面呈现。

#### 3.2 功能清单

| 编号 | 功能点 | 优先级 | 说明 |
|------|--------|--------|------|
| KB-01 | 聊天对话界面 | P0 | 支持多轮对话，展示历史记录 |
| KB-02 | 知识库检索回答 | P0 | 调用外部知识库服务获取回答，展示来源引用 |
| KB-03 | 问题分类 | P1 | 自动识别问题类型（产品知识/销售技巧/其他） |
| KB-04 | 历史记录 | P1 | 保存用户的历史问答记录，支持查看 |
| KB-05 | 推荐问题 | P2 | 基于上下文推荐可能的后续问题 |
| KB-06 | 反馈机制 | P1 | 用户可对回答进行"有用/无用"反馈 |

#### 3.3 交互流程

```
用户输入问题
    │
    ▼
前端发送请求至后端
    │
    ▼
后端拼接上下文（对话历史），调用外部知识库问答服务
    │
    ▼
外部服务返回回答 + 来源引用
    │
    ▼
后端存储记录，返回回答至前端展示
    │
    ▼
用户可继续追问 / 结束
```

#### 3.4 知识库内容范围
- 产品介绍与参数
- 课程体系与价格
- 常见客户疑问及标准回答（FAQ）
- 销售话术与技巧
- 竞品对比分析
- 政策与流程规范

### 模块二：训练系统（核心模块）

#### 3.5 功能描述
用户进入训练大厅，选择模拟客户进行一对一销售对话训练。对话过程中，每条用户消息由后端转发至**外部模拟客户服务**获取回复；对话结束后，后端将完整对话记录发送至**外部教练评分服务**获取评分报告。本系统负责训练流程编排、对话记录存储和评分报告展示。

#### 3.6 功能清单

| 编号 | 功能点 | 优先级 | 说明 |
|------|--------|--------|------|
| TR-01 | 模拟客户列表 | P0 | 展示所有可选的模拟客户卡片 |
| TR-02 | 客户画像展示 | P0 | 每个客户有基本画像（姓名、性格、需求、难度） |
| TR-03 | 对话聊天界面 | P0 | 与模拟客户的实时对话界面 |
| TR-04 | 模拟客户 AI 行为 | P0 | 调用外部模拟客户服务获取回复，前端展示 |
| TR-05 | 对话终止-客户购买 | P0 | 外部服务返回 `is_purchased: true` 时触发结束流程 |
| TR-06 | 对话终止-手动结束 | P0 | 用户主动点击"结束对话"按钮 |
| TR-07 | 教练评分与点评 | P0 | 对话结束后调用外部教练评分服务，展示评分报告 |
| TR-08 | 训练历史 | P1 | 查看历史训练记录和评分趋势 |
| TR-09 | 训练统计 | P1 | 个人训练数据汇总（次数、平均分、进步曲线） |
| TR-10 | 难度标签 | P2 | 客户标注难度等级（简单/中等/困难） |

```
    │

│  └──────┬──────┘  └──────┬──────┘│
```

#### 3.9 教练评分报告

##### 3.9.1 评分维度（由外部教练评分服务定义）

| 维度 | 权重 | 说明 |
|------|------|------|
| 开场破冰 | 15% | 是否自然、专业，能否快速建立信任 |
| 需求挖掘 | 20% | 是否充分了解客户痛点、预算、决策因素 |
| 产品呈现 | 20% | 产品介绍是否清晰、有针对性、突出卖点 |
| 异议处理 | 20% | 面对客户疑虑的应对是否专业、有说服力 |
| 促成成交 | 15% | 是否把握时机推动成交，成交话术是否得当 |
| 沟通技巧 | 10% | 语言表达、情绪管理、倾听能力等综合表现 |

> 注：评分逻辑由外部教练评分服务实现，本系统负责接收评分结果并展示。

##### 3.9.2 评分报告数据结构（外部服务返回格式）

详见 [2.4 外部 AI 服务接口契约 - 教练评分服务](#24-外部-ai-服务接口契约) 部分。

## 四、页面/界面需求

| 页面 | 路径 | 说明 |

- "再练一次"按钮

## 五、技术方案建议

### 5.1 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 跨平台前端 | **Taro 3 / uni-app** | 一套代码编译到 App、H5、微信小程序等多端 |
| PC 客户端 | **Electron** | 基于 Web 技术打包为桌面应用，复用前端代码 |
| App 原生能力 | Capacitor / uni-app 原生插件 | 推送、文件访问等原生能力桥接 |
| 后端 | **Node.js (NestJS) / Python (FastAPI)** | RESTful API 服务 |
| 数据库 | **PostgreSQL** | 业务数据存储（用户、会话、训练记录） |
| 缓存 | **Redis** | 会话状态管理、AI 服务响应缓存 |
| AI 服务通信 | **HTTPS REST API** | 对接外部知识库问答 / 模拟客户 / 教练评分服务 |

> 注：前端跨平台框架需进一步评估 Taro 3 与 uni-app 的适用性，取决于团队技术栈和小程序端的具体要求。

### 5.2 核心 API 设计

```
# 知识库模块
POST   /api/knowledge/chat              # 发送问题，获取回答
GET    /api/knowledge/history            # 获取历史记录

# 训练模块
GET    /api/training/customers           # 获取模拟客户列表
GET    /api/training/customers/:id       # 获取客户详情
POST   /api/training/sessions            # 创建训练会话
POST   /api/training/sessions/:id/chat   # 发送消息
POST   /api/training/sessions/:id/end    # 结束训练
GET    /api/training/sessions/:id/report # 获取评分报告
GET    /api/training/history             # 训练历史列表
GET    /api/training/statistics          # 训练统计数据

# 用户模块
GET    /api/user/profile                 # 用户信息
```

### 5.3 后端 AI 服务代理层设计

后端作为统一网关代理所有外部 AI 服务调用，职责包括：

- **请求转发**：将前端请求按规范转发至对应外部 AI 服务
- **上下文拼接**：维护对话历史，按外部服务要求组装请求参数
- **错误处理**：外部服务超时/异常时的降级策略（重试、提示用户稍后再试）
- **数据存储**：将外部服务返回的结果持久化到数据库
- **流式响应**（可选）：如外部服务支持 SSE/WebSocket，后端透传流式响应给前端

```
前端 ──► 后端 API ──► AI 服务代理层 ──► 外部知识库问答服务
                           ├──► 外部模拟客户对话服务
                           └──► 外部教练评分服务
```

> 注：外部 AI 服务的 Base URL、认证方式（API Key / OAuth 等）、超时配置等通过后端环境变量管理。

## 六、非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 对话响应时间 < 3s（不含外部 AI 服务耗时），评分报告生成 < 10s |

| 外部服务容错 | 外部 AI 服务不可用时，前端友好提示，不阻断其他功能 |
| UI 一致性 | 各平台核心交互一致，允许针对平台特性做适配（如小程序端导航栏规范） |

## 八、开发阶段规划

### Phase 1 - MVP（最小可用版本）
- [ ] 跨平台前端框架搭建（App + H5 + 小程序 + PC）
- [ ] 后端基础框架搭建（用户服务、API Gateway）
- [ ] 外部 AI 服务代理层 + Mock 接口（开发阶段用 Mock，外部服务就绪后切换）
- [ ] 知识库问答页面 + 对话流程
- [ ] 训练大厅（模拟客户列表）
- [ ] 训练对话页面 + 消息收发
- [ ] 训练报告页面 + 评分展示
- [ ] 基础 UI 界面

### Phase 2 - 完善
- [ ] 多轮对话上下文管理优化
- [ ] 评分报告可视化（雷达图等）
- [ ] 训练历史与统计
- [ ] 对接外部 AI 服务（替换 Mock）
- [ ] PC 客户端打包（Electron）
- [ ] 微信小程序适配与提审

### Phase 3 - 增值
- [ ] 训练数据看板（管理视角）
- [ ] 消息推送（训练提醒、报告通知）
- [ ] 离线缓存（小程序端对话记录本地存储）
- [ ] 团队排名与激励
- [ ] 自定义模拟客户配置后台
